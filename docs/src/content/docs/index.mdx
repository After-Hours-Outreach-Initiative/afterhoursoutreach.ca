The After Hours Outreach website helps volunteers apply, prepare for patrols,
and book events, and gives organizers tools to manage volunteers and activities.

The documentation is separated into the following sections:

## Planning

**What is ready, and what needs more thought?**

Work is separated by readiness. Move an item from TBD to TODO once its intended
behavior and scope are clear, and record agreed product behavior in the specification.

- [TODO](/planning/todo/) holds tasks that are ready to work on.
- [TBD](/planning/tbd/) holds ideas, open questions, and proposals that need
  more thought before becoming TODO work.

## Specification

**What should the application do?**

Workflows, permissions, and business rules, readable without knowing the stack.
Agreed behavior that has not been built is explicitly marked as planned.

- [Specification](/specification/) introduces the users and volunteer journey.
- [Site map](/specification/site-map/) lists current website pages and their audience.
- [Accounts](/specification/accounts/) covers applications, sign-in, profiles,
  and organizer access.
- [Events](/specification/events/) covers orientations, patrols, and sign-ups.
- [Discord](/specification/discord/) defines linking, membership, and managed roles.
- [Notifications](/specification/notifications/) defines when people receive email.
- [Privacy](/specification/privacy/) records collection, access, deletion, and
  the documented retention rules.

## Implementation

**How is it built and operated?**

Architecture, code, data, integrations, local development, deployment, and testing.
Technical guides link to the product rules they implement.

- [Implementation](/implementation/) is the starting point for development.
- [System architecture](/implementation/system-architecture/) contains the system
  map, request flow, and environment boundaries.
- [Local development](/implementation/development/) explains local accounts and
  integration simulations.
- [Deployment](/implementation/deployment/) covers previews and production.
- [Email previews](/implementation/emails/) and the [Operations dashboard](/dashboard/)
  provide local inspection tools.

## Keeping the sections useful

Discuss an idea in TBD and move it to TODO when ready. Record its agreed behavior
in Specification, with a planned note if it is unbuilt. Explain the resulting
technical design in Implementation. Link between the sections instead of repeating
requirements.

See [Maintaining these docs](/implementation/docs-site/) for authoring conventions
and the local reader.
